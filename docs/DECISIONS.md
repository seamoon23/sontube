# SonTube Decisions

## D001. YouTube Data API 미사용

MVP에서는 YouTube Data API를 사용하지 않는다.

이유:

- API 비용과 쿼터 부담을 제거한다.
- Google API Key 관리가 필요 없어야 한다.
- 전체 검색과 채널 수집 유혹을 차단한다.
- 보호자 직접 검토라는 제품 철학을 유지한다.

## D002. 전체 검색 미제공

아이 화면 검색은 내부 DB에 저장된 승인 영상만 대상으로 한다.

## D003. 채널/플레이리스트 자동 수집 제외

채널이나 플레이리스트 전체가 안전하다고 보장할 수 없고, 자동 수집에는 외부 API 또는 스크래핑 유혹이 생긴다. MVP에서는 개별 영상 URL만 등록한다.

## D004. 댓글과 자막 분석 제외

댓글과 자막은 품질과 안전성 변동이 크고, 조회/분석을 위해 외부 API나 다운로드 흐름이 필요할 수 있다. MVP에서는 YouTube 플레이어 자체 기능 이상으로 다루지 않는다.

## D005. 자체 영상 업로드 제외

SonTube는 YouTube에 이미 있는 보호자 검토 영상을 정리하는 도구로 시작한다. 저장 비용, 스트리밍 구현, 권리 문제를 피하기 위해 자체 영상 업로드는 제외한다.

## D006. 추천 태그는 내부 데이터 기반

추천 태그는 최근 사용 태그, 자주 사용한 태그, 제목/설명 키워드, 같은 키워드가 포함된 기존 영상의 태그를 기반으로만 만든다. 추천 결과는 자동 적용하지 않고 보호자가 선택한다.

## D007. 아이 화면의 관리 기능 비노출

아이 화면에는 관리자 버튼, 설정 버튼, YouTube 전체 검색, 채널 이동용 UI를 두지 않는다.

## D008. 아이 검색은 제목과 보호자 키워드로 제한

아이 화면 검색은 보호자가 작성한 제목과 검색 키워드만 대상으로 한다. 설명은 관리자 맥락의 메모가 될 수 있으므로 아이 검색 대상에서 제외한다.

## D009. 아이 플레이리스트는 로컬 내 목록으로 시작

MVP 보완에서는 아이 브라우저의 `localStorage`에 저장되는 내 목록으로 시작한다. 부모가 관심사를 확인할 수 있도록 내 목록 담기 신호는 내부 DB에 저장하지만, 아이 화면의 조작감은 단순한 로컬 목록으로 유지한다.

## D010. AI 분석은 API 연동 없이 산출물 export로 검토

아이 피드백과 관심 통계가 쌓이면 외부 AI API를 직접 붙이지 않고, 부모가 복사해서 사용할 수 있는 프롬프트 산출물부터 제공한다.

## D011. 아이 피드백은 짧은 신호로 제한

아이 피드백은 좋아요, 다시 볼래요, 궁금해요, 웃겨요, 어려워요, 별로예요 같은 짧은 버튼으로 제한한다. 복잡한 설문, 점수화, 시청 시간 추적은 MVP에서 제외한다.

## D012. 관심 요약 기간 필터는 URL 상태로 유지

부모 관심 요약은 최근 7일, 최근 30일, 전체를 `period` URL 쿼리로 전환한다. 클라이언트 상태나 복잡한 차트 없이, 부모가 최근 관심과 누적 관심을 가볍게 비교할 수 있게 한다.

## D013. 커스텀 썸네일 삭제는 앱 관리 경로로 제한

커스텀 썸네일 교체나 해제 시 파일 정리는 `/uploads/thumbnails/` 아래의 앱 관리 파일만 대상으로 한다. DB 저장을 먼저 성공시킨 뒤 이전 파일을 best-effort로 삭제하여 영상 데이터 손상을 피한다.

## D014. 부모 타겟 가족용 서비스로 포지셔닝

SonTube 앱 배포 방향은 어린이 카테고리 앱이 아니라 부모가 관리하는 가족용 서비스로 둔다. 아이가 보는 화면은 제한 시청 클라이언트이며, 구매/설정/관리의 주체는 부모다.

## D015. 앱 키 기반 비동기 동기화

앱은 관리자 웹에서 생성한 앱 키를 등록한 뒤 `/api/app/register`와 `/api/app/sync`를 통해 승인 영상 카탈로그 JSON만 가져간다. 원문 키는 저장하지 않고 SHA-256 해시와 접두어만 DB에 저장한다.

## D016. 무료 체험 14일과 결제 보류

무료 체험은 앱 키 생성일 기준 14일이다. 결제는 MVP에서 구현하지 않고, 앱스토어/플레이스토어 배포 정책 확인 후 웹 관리자 결제 또는 인앱 결제 중 하나를 결정한다.

## D017. 아이 앱 광고 없음

아이 앱에는 광고를 넣지 않는다. 관리자 화면에는 하단 광고/후원 슬롯을 둘 수 있다. YouTube iframe 자체 광고는 차단하거나 변조하지 않고 안내만 제공한다.

## D018. 앱 키는 설치 단위로 바인딩

앱 키는 최초 등록 요청의 설치 ID에 바인딩한다. 같은 원문 키가 다른 설치 ID에서 사용되면 거부하여 키 복제의 영향을 줄인다.

## D019. 앱 설정은 부모 확인 뒤 노출

최초 키 등록 이후 `/app` 설정 화면은 간단한 부모 확인을 통과해야 열린다. 저장된 원문 키는 앱 화면에 다시 채워 넣지 않는다.

## D020. 앱 래퍼는 path-level 네비게이션 차단 필요

Android WebView 래퍼는 origin allowlist만으로는 부족하다. 같은 origin의 `/admin`, `/kids`, 임의 경로 접근을 막고 `/app` 중심의 상위 네비게이션만 허용해야 한다.

## D021. Android 앱은 부모 통신 정책을 선확인

부모 관리자는 `관리자 화면 > 대시보드 > 앱 접속 정책`에서 승인 목록 수신 환경을 Wi-Fi 전용 또는 모든 네트워크로 정한다. Android 앱은 WebView를 시작하기 전에 `/api/app/policy`를 확인하고, 정책 확인 실패는 `Wi-Fi 필수=true`로 처리한다. 정책을 만족하지 못하거나 서버에 닿지 못하면 실제 승인 목록과 YouTube 플레이어 대신 재생되지 않는 로컬 샘플만 표시한다.

## D022. 접속마다 카탈로그 버전을 확인하고 변경 시에만 목록 수신

앱은 시작과 전면 복귀마다 기존 앱 키와 로컬 `catalogVersion`으로 최신 여부를 확인한다. 서버 버전이 같으면 목록 본문을 보내지 않고, 달라진 경우에만 새 승인 카탈로그 전체를 보낸다. 이 흐름으로 수동 다시 불러오기 버튼은 제거한다. 교체용 앱 키는 서버 등록과 카탈로그 수신이 모두 성공한 뒤에만 기존 저장 키와 캐시를 바꾼다.

## D023. 이용 상태 표시는 부모 관리자 화면에 한정

14일 체험과 향후 유료 entitlement 판정은 유지하되 아이 앱 헤더와 설정에는 무료 체험 카드나 종료일을 표시하지 않는다. 결제·이용 상태 확인은 부모 관리자 화면의 책임으로 둔다.

## D024. 가족별 데이터 경계

부모 계정은 하나의 `Family`에 속하고 영상, 태그, 앱 키, 아이 반응, 결제와 이용권 조회·수정은 세션의 `familyId`로 제한한다. 기존 전역 데이터는 bootstrap 가족에 귀속한다. Android 설치 ID는 단말에 고정 저장하고 앱 키가 속한 가족의 통신 정책과 승인 카탈로그만 받는다.

## D025. 초기 유료 운영은 사업용 계좌이체와 수동 승인

D016의 결제 보류 결정을 갱신한다. PG, 카드, 인앱결제와 자동갱신 없이 90일·365일 선불 이용권을 제공한다. 신청 시 서버 상품 가격을 스냅샷으로 저장하고, 최종관리자가 실제 입금을 확인한 뒤 하나의 트랜잭션에서 결제 승인과 이용권 생성·연장을 처리한다.

## D026. 최종관리자는 환경변수 전용 계정으로 분리

최종관리자 인증은 보호자 DB 계정과 분리된 `SUPERADMIN_*` 환경변수와 별도 세션 비밀키를 사용한다. 보호자를 최종관리자로 승격하는 DB 권한은 만들지 않는다. 대체 로그인은 비밀번호 재확인·사유·30분 제한·지속 배너·감사 로그를 요구하며 결제와 계정 보안 변경은 차단한다.

## D027. 환불은 전액·최신 지급 건부터 시작

초기 환불은 운영자가 실제 송금을 완료한 후 전액 환불로만 기록한다. 가장 최근 활성 `SubscriptionGrant`만 자동 취소하며 이후 연장 건이 있으면 자동 처리를 중단한다. 부분 환불과 기간 비례 산식은 정책 확정 뒤 구현한다.

## D028. 현금영수증 식별정보는 결제 폼에서 수집하지 않음

암호화·마스킹·보존 정책이 준비되기 전에는 휴대전화번호와 사업자번호를 결제 신청 DB에 저장하지 않는다. 현금영수증 요청은 신청번호를 기준으로 고객지원에서 별도로 받고, 안전한 전용 모델이 준비된 뒤 자동화를 검토한다.

## D029. 채널은 가족별 수동 마스터로 관리하고 승인 목록 안에서만 탐색

채널은 YouTube에서 자동 조회하거나 수집하지 않고 가족별 `Channel` 마스터로 관리한다. 보호자는 개별 영상 등록·수정 시 기존 채널을 선택하거나 새 채널명을 직접 입력하며, 영상은 선택적인 `Video.channelId`로 채널과 연결한다. 기존 영상은 채널 미지정 상태로 호환한다.

아이 앱 카탈로그의 채널 정보는 nullable이고, 같은 채널 보기 동작은 현재 가족 카탈로그에 포함된 승인·공개 영상만 `channelId`로 로컬 필터링한다. 외부 YouTube 채널 이동, 채널 전체 영상 자동 수집, YouTube Data API 사용은 하지 않는다.
## D030. 채널 비활성화는 신규 선택만 숨기고 병합은 같은 가족 안에서 처리

채널 비활성화는 영상 등록·수정 화면의 신규 선택 목록에서만 채널을 숨긴다. 기존 `Video.channelId` 연결, 관리자 필터와 아이 앱의 같은 채널 묶음은 유지하여 이미 승인된 카탈로그가 갑자기 달라지지 않게 한다.

중복 채널 병합은 현재 로그인한 보호자의 같은 `Family` 안에서 활성 대상 채널로만 허용한다. 트랜잭션 안에서 원본 채널의 영상을 대상 채널로 이동한 뒤 원본 채널을 삭제한다. 이름 변경은 공백·대소문자 등을 정규화한 가족별 중복 이름을 거부하고 병합 사용을 안내한다.

## D031. Android 통신 정책은 실행 중 네트워크 전환에도 fail-closed 적용

Android 앱이 화면에 보이는 동안 기본 네트워크의 연결·전송 방식·검증 상태가 바뀌면 기존 WebView와 전체 화면 재생을 먼저 숨긴다. 오프라인이면 즉시 네이티브 샘플 화면으로 전환하고, Wi-Fi와 모바일 데이터 사이를 이동하거나 네트워크가 교체되면 서버 정책을 다시 확인한 뒤에만 WebView를 복원한다. 빠르게 연속되는 변경은 진행 중 요청 하나와 최신 재확인 하나로 합친다.

## D032. 공개 배포 전까지 중요 요청은 상한이 있는 프로세스 로컬 rate limit 사용

보호자·최종관리자 로그인, 앱 동기화, 결제·환불 요청은 고정 시간창 rate limit을 공유한다. 식별자는 원문 대신 SHA-256 해시를 사용하고, 활성 버킷 수에 상한을 둬 메모리 증가를 제한한다. 이 방식은 단일 프로세스 MVP 방어선일 뿐이므로 다중 인스턴스 공개 배포 전에는 신뢰 프록시 설정을 확정하고 Redis 같은 공유 저장소 기반 제한으로 교체한다.

## D033. Android 설정 보호는 기기 자격 증명을 우선 사용

앱 키가 등록된 Android 앱에서 설정 열기와 키 교체는 운영체제의 PIN·패턴·비밀번호 확인을 우선 사용한다. 현재 산수 문제는 일반 브라우저 QA용 보조 장치일 뿐 보안 인증으로 간주하지 않는다. 인증 성공은 설정 진입 한 번에만 사용하고 background 이동 시 폐기한다. 1차 구현에서 별도 SonTube PIN을 만들지 않으며, 자세한 위협 범위와 복구·QA 기준은 `docs/ANDROID_PARENT_AUTH_DESIGN.md`를 따른다.

## D034. 웹과 Android는 하나의 저장소에서 관리하고 전달 파이프라인은 분리

웹과 `android-client/`는 당분간 SonTube 저장소 하나에서 함께 관리한다. 앱 카탈로그 계약과 Android 네트워크·탐색 정책이 웹 API와 함께 바뀌기 때문에 저장소를 미리 나누지 않는다. 대신 웹 검증·배포와 Android 로직 검증·APK/AAB 산출물은 서로 독립된 CI 작업과 승인 절차를 사용한다. 웹만 바뀐 커밋이 Android 배포를 만들거나, Android 산출물 작업이 웹 운영 배포를 자동으로 바꾸지 않게 한다.

## D035. 공개 웹은 부모용 소개와 명시 공개된 Lite 카탈로그로 제한

공개 `/`는 부모를 위한 제품 소개와 사용 흐름 안내다. 공개 `/lite`는 운영자가 별도로 `Lite 공개`한 영상 중 `보호자 확인 완료`, `아이 화면 공개`, 활성 가족 조건까지 모두 만족한 영상만 모은 읽기 전용 공용 체험이다. 초기 Lite는 검색 노출 목적이 아니므로 `noindex`로 운영한다. 검색봇이 `noindex`를 읽을 수 있도록 Lite page/API crawl은 허용한다. 가족별 관리자 카탈로그 전체를 공개하거나, 가족 ID·원본 URL·앱 키·결제·이용권 데이터를 Lite 응답에 포함하지 않는다. 공개 대상이 0개이면 빈 상태를 보여주며 샘플이나 Android의 비공개 캐시로 대체하지 않는다.

Lite는 공개 목록 안의 제목·보호자 키워드 검색, 태그·채널 필터, 같은 채널의 공개 영상 보기, YouTube iframe 재생·전체 화면과 브라우저 `localStorage` 내 목록만 제공한다. 앱 키 등록, 가족별 승인 목록, 서버 피드백, 관심 통계, 결제, Android 기기 잠금과 Wi-Fi 강제는 제공하지 않는다. 제한형 시청과 가족별 정책이 필요하면 Android `/app`을 사용한다.

공개 카탈로그 성공 응답은 요청별 `generatedAt` 차이를 허용하는 weak ETag와 `Cache-Control: public, max-age=0, s-maxage=60, must-revalidate`를 사용한다. 브라우저는 매번 재검증하고 공유 CDN은 최대 60초까지만 재사용해 공개 차단이 오래 지연되지 않게 한다. 오류 응답은 `private, no-store`로 캐시하지 않는다. 체크인된 JSON Schema를 실제 route의 200 응답에 적용하고 304·503 경계를 CI에서 검증한다.

## D036. 관리자 접근은 애플리케이션 인증과 Cloudflare Access를 함께 사용

`/admin`은 `ADMIN_ALLOWED_EMAILS`에 명시한 운영 보호자 두 계정만 허용하고, 활성 `ParentUser` 확인과 기존 세션 검증을 계속 적용한다. `/superadmin`은 별도 `SUPERADMIN_*` 자격 증명을 가진 소유자 한 명만 사용한다. Cloudflare Access는 이 인증을 대체하지 않고 배포 도메인 앞의 추가 경계로 둔다. 관리자용 Access 정책에는 같은 두 이메일을, 최종관리자 정책에는 소유자 이메일 하나만 등록한다.

Access는 관리자 경로에만 적용한다. 공개 `/`, `/lite`, `/api/lite/*`와 Android에 필요한 `/app`, `/api/app/*`에는 Access 로그인이나 광범위한 호스트 정책을 씌우지 않는다. `/api/app/*`는 자체 앱 키·설치 ID 검증을 유지한다. Access 경로의 `*`는 부모 경로 자체를 포함하지 않으므로 `/admin`과 `/admin/*`, `/superadmin`과 `/superadmin/*`를 각각 함께 설정한다.

## D037. 현재 운영 배포와 Cloudflare Pages·Supabase 전환을 분리

현재 웹은 동적 Next.js 서버, Prisma/SQLite 쓰기와 `public/uploads/thumbnails/` 로컬 파일 쓰기에 의존한다. 따라서 현 상태를 Cloudflare Pages의 정적 출력으로 바로 배포하지 않는다. 1차 운영은 영구 디스크가 있는 단일 Node 서버에 웹·SQLite·업로드를 함께 두고 Cloudflare DNS·TLS·Access를 앞단에 배치한다. DB와 업로드는 같은 시점으로 백업·복구한다.

후속 단계에서는 SonTube 전용 Supabase 프로젝트로 PostgreSQL·Auth·RLS·Storage·권한 Edge Function을 이관하고, 웹을 정적 SPA/PWA로 재구성한 뒤 SonTube 전용 Cloudflare Pages 프로젝트에 배포한다. `jjunybox.com` DNS 존과 Cloudflare 계정만 공유하며 Museum·Arcade 또는 다른 서비스의 Supabase 프로젝트, 데이터, service role과 배포 설정은 공유하지 않는다.

## D038. 보호자 세션은 버전으로 폐기하고 대체 로그인은 읽기 전용으로 제한

보호자 세션에는 `ParentUser.sessionVersion`을 서명하고 매 요청마다 현재 DB 값과 비교한다. 비밀번호 재설정, 보호자 활성 상태 변경, 가족 활성 상태 변경 시 관련 버전을 증가시켜 기존 7일 세션과 30분 대체 로그인 세션을 즉시 무효화한다. `ADMIN_ALLOWED_EMAILS`는 정규화한 서로 다른 이메일 정확히 두 개일 때만 유효하다.

최종관리자의 대체 로그인은 버그 재현과 화면 확인만 위한 읽기 전용 세션이다. 영상과 Lite 공개, 태그, 채널, 앱 키, Wi-Fi 정책, 아이 반응, 결제 등 보호자 화면의 모든 변경을 서버 액션에서 차단한다. 종료와 로그아웃은 감사 저장소 장애가 있어도 인증 쿠키를 먼저 폐기한다.

현재 Lite 공개 권한은 이 두 운영 보호자 계정에 한정한다. 향후 일반 보호자 관리 계정을 개방하기 전에는 Lite 공개 전용 운영자 역할과 변경 감사 로그를 별도로 추가하며, 단순 `ParentUser` 로그인만으로 전역 공개 권한을 주지 않는다.

## D039. 1차 SQLite 운영은 사전점검·쓰기 중지 백업·복구 훈련을 전제로 함

운영 `DATABASE_URL`은 영구 볼륨의 절대 SQLite `file:` 경로만 사용하고, 세션 비밀키·두 보호자 allowlist·최종관리자와 수동 결제 필수 설정은 실제 값을 출력하지 않는 사전점검을 통과해야 한다. `/api/health`는 DB 읽기 성공 여부만 200/503과 no-store로 반환하고 경로·버전·오류 원문을 노출하지 않는다.

SQLite 스냅샷은 `VACUUM INTO`, 커스텀 썸네일은 SHA-256 manifest로 백업·검증한다. DB와 파일 업로드를 하나의 트랜잭션으로 묶을 수 없으므로 백업과 복구 중에는 애플리케이션 쓰기를 멈춘다. 복구는 기본적으로 기존 대상을 덮어쓰지 않고 dry-run과 manifest 검증을 먼저 요구하며, `--force` 교체는 별도 사본을 확보한 운영자만 수행한다. archive 성공 검증만으로 완료로 보지 않고 정기적인 staging 복구 훈련을 운영 조건으로 둔다.

Android debug APK CI artifact는 개발·QA 편의를 위한 기본 debug signing 산출물이며 릴리스 서명이나 스토어 배포 승인을 대신하지 않는다.
